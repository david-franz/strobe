# 04 — The napi-rs native bridge

## Purpose

This feature is the bridge between the two planes: the `napi-rs` addon that lets in-process TypeScript call the Rust engine. It satisfies the **native** row of the bridge table in [architecture.md](../../architecture.md#the-bridge-ts--rust) — *Rust spawns and owns the `cpal` audio thread; TS calls in-process* — and implements the Phase 0 subset of the `Engine` control-call surface from [event-protocol.md](../../event-protocol.md#control-call-surface-non-real-time). It is deliberately the smallest thing that honors the locked layout: the "Phase 0 simplification" where the transport is a single `pushEvents(ArrayBuffer)` napi call per scheduler tick that copies into the Rust ring, and only `NoteOn` + `Tempo` opcodes are interpreted ([event-protocol.md](../../event-protocol.md#phase-0-simplification)).

The whole point of the bridge is that the TypeScript library targets this small interface and nothing above it knows whether the backend is the native addon or (later) WASM/AudioWorklet. So the four methods here — `start`, `stop`, `pushEvents`, `stats` — are exactly the methods the scheduler ([05-lookahead-scheduler.md](05-lookahead-scheduler.md)) and runtime ([07-hot-reload-demo.md](07-hot-reload-demo.md)) call.

## Design

### Build setup (no node-gyp)

`napi-rs` builds the addon with the pure Rust/JS toolchain — no node-gyp, no Python — and supports prebuilt per-OS binaries so end users eventually install with `npm i` ([architecture.md](../../architecture.md#why-these-technology-choices)).

```toml
# bindings/native/Cargo.toml
[package]
name = "tekno-native"
edition = "2021"

[lib]
crate-type = ["cdylib"]

[dependencies]
napi = { version = "2", default-features = false, features = ["napi8"] }
napi-derive = "2"
engine = { path = "../../engine" }

[build-dependencies]
napi-build = "2"
```

```rust
// bindings/native/build.rs
fn main() { napi_build::setup(); }
```

```jsonc
// bindings/native/package.json (excerpt)
{
```

`napi build` emits the `*.node` binary, an `index.js` loader, and `index.d.ts` typings — no node-gyp anywhere in the chain.

### How Rust owns/spawns the cpal thread

The `#[napi]` wrapper holds an `engine::Engine` (the pure-Rust struct from [01-audio-io-cpal.md](01-audio-io-cpal.md)). `start()` opens the `cpal` stream; **cpal spawns and owns the real-time audio thread** internally, and the `Stream` handle lives inside the `Engine`. TS never sees or touches that thread; it only calls these four methods on the addon, which run on Node's thread (or a libuv worker for async ones). The `pushEvents` path reaches the audio thread only through the lock-free ring ([02-event-ring-buffer.md](02-event-ring-buffer.md)), never by sharing a lock with it.

```rust
// bindings/native/src/lib.rs
use napi::bindgen_prelude::*;
use napi_derive::napi;

#[napi]
pub struct Engine {
    inner: engine::Engine, // owns cpal Stream, ring producer, frame clock, stats
}

#[napi]
impl Engine {
    #[napi(constructor)]
    pub fn new() -> Self {
        Engine { inner: engine::Engine::new() } // builds ring + clock + idle kick; no stream yet
    }

    /// Open the cpal output stream. cpal spawns/owns the audio thread.
    #[napi]
    pub fn start(&mut self, opts: Option<StartOpts>) -> Result<()> {
        let (sr, bf) = match opts {
            Some(o) => (o.sample_rate.map(|x| x as u32), o.buffer_frames.map(|x| x as u32)),
            None => (None, None),
        };
        self.inner.start(sr, bf).map_err(to_napi)
    }

    #[napi]
    pub fn stop(&mut self) -> Result<()> {
        self.inner.stop(); // drops the Stream → audio thread torn down cleanly
        Ok(())
    }

    /// Hot path: copy N×32 bytes into the ring. Non-blocking. One call per tick.
    #[napi]
    pub fn push_events(&self, buffer: Buffer) -> Result<()> {
        // `Buffer` is a zero-copy view of the JS ArrayBuffer's bytes.
        let bytes: &[u8] = buffer.as_ref();
        self.inner.push_events(bytes).map_err(to_napi) // validates length, casts, push_batch
    }

    #[napi]
    pub fn stats(&self) -> Stats {
        let s = self.inner.stats();
        Stats {
            current_frame: s.current_frame as f64, // u64 → f64 (safe < 2^53; ~570 yrs @48k)
            underruns:     s.underruns as f64,
            late_events:   s.late_events as f64,
            ring_fullness: s.ring_fullness as f64,  // 0.0..1.0
        }
    }
}

#[napi(object)]
pub struct StartOpts { pub sample_rate: Option<f64>, pub buffer_frames: Option<f64> }

#[napi(object)]
pub struct Stats {
    pub current_frame: f64,
    pub underruns: f64,
    pub late_events: f64,
    pub ring_fullness: f64,
}
```

### How `pushEvents` copies into the ring without blocking

`pushEvents` runs on the JS thread but must never block the scheduler. It does only: bounds-check the length is a multiple of 32, `bytemuck`-cast the bytes to `&[EventRecord]` ([02-event-ring-buffer.md](02-event-ring-buffer.md)), and `producer.push_batch(recs)` — each `try_push` is a couple of atomic ops and a memcpy of 32 bytes into a pre-allocated slot. If the ring is full it **drops and increments a counter** rather than blocking ([event-protocol.md](../../event-protocol.md#the-event-ring-buffer)). There is no lock shared with the audio thread, so even though this is a synchronous napi call it cannot stall on the real-time side.

```rust
// engine/src/lib.rs (the method push_events wraps)
impl Engine {
    pub fn push_events(&self, bytes: &[u8]) -> Result<(), EngineError> {
        let recs = event::records_from_bytes(bytes).map_err(|_| EngineError::BadLength)?;
        let dropped = self.producer.push_batch(recs); // non-blocking; full → drop+count
        if dropped > 0 { self.stats.ring_full_drops.fetch_add(dropped as u64, Relaxed); }
        Ok(())
    }
}
```

`pushEvents` is intentionally **synchronous** (not async): it is cheap (microseconds) and the scheduler wants it to complete within its tick. The expensive/async control calls (`defineInstrument`, `loadSample`) don't exist yet in Phase 0.

### The TS engine interface

`packages/tekno/src/engine.ts` declares the interface the rest of the library targets and loads the addon:

```ts
// packages/tekno/src/engine.ts
export interface EngineStats {
  currentFrame: number;   // engine frame counter (source of truth)
  underruns: number;
  lateEvents: number;
  ringFullness: number;   // 0..1
}

export interface Engine {
  start(opts?: { sampleRate?: number; bufferFrames?: number }): Promise<void>;
  stop(): Promise<void>;
  pushEvents(buffer: ArrayBuffer): void;   // hot path; non-blocking; once per tick
  stats(): EngineStats;
}

// Native backend: thin wrapper over the napi addon.
import { Engine as NativeEngine } from "@tekno/native"; // generated index.d.ts

export function createNativeEngine(): Engine {
  const e = new NativeEngine();
  return {
    start: async (o) => e.start(o),
    stop:  async () => e.stop(),
    pushEvents: (buf) => e.pushEvents(Buffer.from(buf)), // Buffer view, no copy in JS
    stats: () => e.stats(),
  };
}
```

> The interface matches [event-protocol.md](../../event-protocol.md#control-call-surface-non-real-time) trimmed to the Phase 0 four methods; `defineInstrument`/`loadSample` are added (not changed) in later phases. Moving to the WASM/AudioWorklet backend later swaps `createNativeEngine` for `createWebEngine` and changes no song code.

## Interfaces

- **To [05-lookahead-scheduler.md](05-lookahead-scheduler.md):** the scheduler calls `engine.pushEvents(buffer)` once per ~25 ms tick with a reusable `ArrayBuffer` of N×32 bytes, and reads `engine.stats().currentFrame` to align its frame computations.
- **To [07-hot-reload-demo.md](07-hot-reload-demo.md):** the runtime calls `start`/`stop` and polls `stats()` for the zero-underruns/zero-late verification.
- **To [01](01-audio-io-cpal.md)/[02](02-event-ring-buffer.md)/[03](03-kick-voice.md):** `start`→`engine::Engine::start`, `pushEvents`→`producer.push_batch`, `stats`→reads the shared `AtomicU64` frame clock and stat atomics.
- **Event protocol:** carries the raw 32-byte records unmodified; the bridge neither parses nor reorders them. Phase 0 interprets only `NoteOn` and `Tempo` downstream.

## Edge cases & risks

- **`pushEvents` must not block the scheduler.** Guaranteed by the lock-free ring; full → drop + count, never wait. *Risk:* if someone made `pushEvents` `async` it could be delayed behind the libuv pool — it stays sync.
- **`u64` → `f64` for `currentFrame`.** `f64` exactly represents integers below 2^53; at 48 kHz that is ~570 years, far beyond any session — safe.
- **Buffer lifetime.** `napi::Buffer` borrows the JS bytes only for the duration of the call; we copy into the ring before returning, so no dangling reference. The TS side reuses one `ArrayBuffer` across ticks ([05](05-lookahead-scheduler.md)); since `pushEvents` copies synchronously, reuse is safe.
- **Bad length.** A buffer not a multiple of 32 returns `EngineError::BadLength` (a thrown JS error) without touching the ring — caught in scheduler tests.
- **start/stop ordering.** `start` is idempotent ([01](01-audio-io-cpal.md)); `pushEvents`/`stats` before `start` are harmless (events sit in the ring; `currentFrame` is 0). `stop` then `pushEvents` just fills the ring with nothing draining — acceptable; runtime stops pushing after `stop`.
- **Native build / packaging.** Phase 0 builds locally with `napi build`. Prebuilt per-OS binaries (so `npm i` needs no Rust) are a Phase-5 packaging concern ([roadmap.md](../../roadmap.md#phase-5--live-coding-dx)); the build path here is already node-gyp-free.

## Acceptance criteria

- [ ] **Addon builds with no node-gyp.** *How to test:* `cd bindings/native && npm run build` produces a `*.node` + `index.d.ts` on macOS with only the Rust + `@napi-rs/cli` toolchain (no Python/node-gyp invoked).
- [ ] **Round-trip start→push→stats→stop from Node.** *Test (Node script / vitest):* `const e = new NativeEngine(); await e.start({sampleRate:48000,bufferFrames:256}); e.pushEvents(oneNoteOnAt(e.stats().currentFrame + 4800)); ` wait 200 ms; assert `e.stats().currentFrame` advanced ≈ 9600 and `underruns === 0 && lateEvents === 0`; `await e.stop()`.
- [ ] **`pushEvents` is non-blocking & synchronous.** *Test:* time 1000 `pushEvents` calls of a full window; assert each returns in well under a millisecond and the call signature is sync.
- [ ] **Full-ring drop is counted, not thrown/blocked.** *Test:* push far more than ring capacity without the stream running to drain; assert no throw/hang and a ring-full drop counter (surfaced via `ringFullness`/stats) is nonzero.
- [ ] **Stats shape & types.** *Test:* `stats()` returns `{currentFrame, underruns, lateEvents, ringFullness}` all `number`, with `ringFullness` in `[0,1]`.
- [ ] **Interface parity.** *How to test:* `createNativeEngine()` returns an object structurally matching the `Engine` interface (TypeScript compiles `engine.ts` with no `any` escapes).
