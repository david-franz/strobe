# 01 — Oscillator bank

## Purpose

The oscillator is the "base frequency" the project is named around: a raw tone you sculpt
into everything else. This feature provides the bank of `fundsp` generators every synth
voice picks one of — **sine, saw, square (with pulse-width), triangle, noise, and a
wavetable oscillator** — each driven by a frequency taken from the `NoteOn` event and each
behaving correctly on retrigger. Saw/square/triangle must be **band-limited** so high notes
don't alias into harsh inharmonic garbage.

## Location

```
engine/src/voices/oscillator.rs   # the bank: OscKind, builders, wavetable storage (new)
engine/src/voices/mod.rs          # re-export OscKind (new)
engine/src/graph.rs               # picks an oscillator from InstrumentConfig (extended)
```

The oscillator is consumed by the synth voice ([04-synth-voice.md](04-synth-voice.md)) and
the drum kit ([05-drum-synthesis.md](05-drum-synthesis.md)); it is never instantiated on
its own.

## Design

### `OscKind` — what the TS layer selects

```rust
/// Selected per-instrument by InstrumentConfig (see event-protocol.md control calls).
#[derive(Clone, Copy, Debug, PartialEq)]
pub enum OscKind {
    Sine,
    Saw,
    Square,             // pulse width in OscConfig.pulse_width (0.0..1.0, 0.5 = square)
    Triangle,
    Noise,              // white noise; frequency-independent
    Wavetable(u32),     // id into the engine's wavetable bank
}

#[derive(Clone, Copy, Debug)]
pub struct OscConfig {
    pub kind: OscKind,
    pub pulse_width: f32,   // only meaningful for Square; 0.01..0.99, default 0.5
    pub phase_reset: bool,  // reset phase to 0 on retrigger? default true (see below)
}
```

### Band-limiting / anti-aliasing

A naive `saw`/`square` generated by wrapping a phasor has infinite harmonics and aliases
badly above a few hundred Hz. We use fundsp's **band-limited** oscillator opcodes, which
are the project's chosen primitives:

- `saw()` — band-limited sawtooth.
- `square()` — band-limited square.
- `triangle()` — band-limited triangle.
- `pulse()` — band-limited pulse with a **second input** for pulse width, which is how we
  implement PWM.
- `sine()` — a pure sinusoid needs no band-limiting.
- `noise()` — white noise; no pitch, so no aliasing concern.

These take frequency as an input signal, so we drive them from a constant (or a modulated
signal later). This keeps us from hand-writing a **PolyBLEP** correction — fundsp's
band-limited generators already solve aliasing. (PolyBLEP is the fallback only if we ever
need a custom waveform fundsp doesn't provide; noted here so the choice is explicit.)

### Frequency input — from `NoteOn.arg0`

Per the [event protocol](../../event-protocol.md#opcodes), `NoteOn` carries the frequency
in **`arg0` (Hz)** — the pitch is already resolved to Hz in TS (`note("c2")` → 65.41 Hz),
so the engine never parses note names. The voice feeds that Hz value into the oscillator's
frequency input as a constant signal:

```rust
// freq_hz comes straight from the NoteOn event's arg0.
let osc = constant(freq_hz) >> saw();          // band-limited saw at freq_hz
```

For pulse-width / PWM we stack frequency and width into the two inputs of `pulse()`:

```rust
// Square via pulse(): (freq | width) >> pulse()
let osc = (constant(freq_hz) | constant(pulse_width)) >> pulse();
```

### fundsp graph sketches (one per kind)

```rust
use fundsp::hacker::*;

/// Build the bare oscillator generator at a fixed frequency.
/// Returns a boxed AudioUnit so all kinds share one type at the call site.
pub fn build_osc(cfg: OscConfig, freq_hz: f32, wt: &WavetableBank) -> Box<dyn AudioUnit> {
    match cfg.kind {
        OscKind::Sine     => Box::new(constant(freq_hz) >> sine()),
        OscKind::Saw      => Box::new(constant(freq_hz) >> saw()),
        OscKind::Square   => {
            let w = cfg.pulse_width.clamp(0.01, 0.99);
            Box::new((constant(freq_hz) | constant(w)) >> pulse())
        }
        OscKind::Triangle => Box::new(constant(freq_hz) >> triangle()),
        OscKind::Noise    => Box::new(noise()),                 // freq ignored
        OscKind::Wavetable(id) => Box::new(wt.osc(id, freq_hz)), // see below
    }
}
```

### Wavetable oscillator

A wavetable osc reads a single-cycle waveform from a pre-loaded table, interpolated, and
mip-mapped for band-limiting (lower tables for higher notes). fundsp provides a
`Wave`-backed table reader; we wrap it in an engine-owned bank so tables are uploaded via a
**control call** (non-real-time), never allocated on the audio thread.

```rust
/// Pre-allocated, immutable-during-playback bank of single-cycle wavetables.
/// Tables are uploaded via a defineInstrument()/loadSample()-style control call
/// and double-buffered swapped in between buffers (no alloc on the audio thread).
pub struct WavetableBank {
    tables: Vec<Arc<Wavetable>>,   // built off-thread; audio thread only reads
}

impl WavetableBank {
    /// Returns a generator reading table `id` at `freq_hz`, band-limited via fundsp's
    /// Wavetable (which holds per-octave band-limited copies).
    pub fn osc(&self, id: u32, freq_hz: f32) -> An<impl AudioNode> {
        let table = self.tables[id as usize].clone();
        constant(freq_hz) >> wavetable(table)   // fundsp band-limited wavetable reader
    }
}
```

The bank is built before `start()`; the audio thread only clones `Arc`s (cheap, no
allocation of audio data) and reads. New tables added live arrive through the same
double-buffered, atomically-swapped state path the protocol doc specifies for control
calls.

### Phase reset on retrigger

`phase_reset` controls what happens when the same physical voice is retriggered by a new
`NoteOn`:

- **`true` (default):** the oscillator's phase is reset to 0 at note start. This gives a
  consistent, punchy attack transient — essential for the kick (a pitched sine that must
  start at the same phase every hit for a tight thump) and generally desirable for
  percussive/plucky sounds.
- **`false` (free-running):** phase continues from where it was. Smoother for sustained
  pads; avoids a click if the previous note was mid-cycle at a high amplitude.

Because Phase 1 rebuilds (or re-`reset()`s) the voice's fundsp graph on each `NoteOn` (see
[06-voice-allocation.md](06-voice-allocation.md)), the practical implementation is: call
`node.reset()` on retrigger when `phase_reset` is true; skip it otherwise. The amp envelope
([03-envelopes.md](03-envelopes.md)) still ramps from zero so even a phase reset is
click-free.

### Parameter list & ranges

| Param | Range | Default | Notes |
| --- | --- | --- | --- |
| `kind` | enum | Sine | selected by TS `.saw()`/`.square()`/… |
| `freq_hz` | 20 .. 20000 | — | from `NoteOn.arg0`; clamped to Nyquist |
| `pulse_width` | 0.01 .. 0.99 | 0.5 | Square only; live-settable via `ParamSet` |
| `phase_reset` | bool | true | per-instrument |
| wavetable `id` | 0 .. N-1 | — | index into `WavetableBank` |

## Interfaces

- **Event protocol** ([event-protocol.md](../../event-protocol.md#opcodes)):
  - `NoteOn` (`0x01`) `arg0` = frequency in Hz → oscillator frequency input.
  - `ParamSet` (`0x10`) can retune `pulse_width` (and later, wavetable position) on a live
    voice; the param id namespace for oscillator params is allocated in
    [04-synth-voice.md](04-synth-voice.md).
- **Voice allocation** ([06-voice-allocation.md](06-voice-allocation.md)): the allocator
  hands the chosen physical voice the `freq_hz` from `arg0` and triggers/rebuilds its osc.
- **Song API:** the TS modifiers `.sine() .saw() .square(pw?) .tri() .noise() .wavetable(name)`
  set `OscKind`/`pulse_width` in the `InstrumentConfig` sent by `defineInstrument()` (see
  [04-synth-voice.md](04-synth-voice.md)). They do **not** emit per-note events for the
  waveform choice; the choice is baked into the instrument.

## Edge cases & risks

- **Aliasing:** mitigated by using fundsp's band-limited `saw/square/pulse/triangle` and a
  mip-mapped wavetable. Acceptance includes an FFT null check that high notes stay below an
  aliasing threshold.
- **Real-time safety:** no oscillator builder allocates on the audio thread for the
  built-in kinds (they're stack-composed fundsp nodes). Wavetables are `Arc`-cloned only.
  Graph (re)building on `NoteOn` must reuse pre-allocated voice slots — never `Box::new` on
  the hot path for the steady-state case; see voice-allocation's pre-built-pool approach.
- **Denormals:** sine/saw/etc. don't produce denormals at output, but the downstream filter
  can; denormal flushing is handled in [02-filters.md](02-filters.md). Noise never
  denormals.
- **Clicks:** prevented by the amp envelope (03), not by the oscillator. A free-running osc
  (`phase_reset:false`) avoids the *retrigger* click; a phase-reset osc relies on the
  envelope's zero-start attack.
- **CPU:** band-limited generators cost more than naive ones; budget ~1–2 µs/voice for the
  osc stage at 48 kHz. 16 voices (the target) stay well within a 5.3 ms buffer.
- **Nyquist clamp:** `freq_hz` is clamped to `< sampleRate/2` so an absurd `note()` can't
  produce a DC or aliased tone.

## Acceptance criteria

- [ ] Each `OscKind` produces the expected spectrum: sine = single partial; saw = all
      harmonics ~1/n; square = odd harmonics; triangle = odd harmonics ~1/n²; noise = flat.
      **Test:** render 1 s, FFT, assert partial structure.
- [ ] A 4 kHz saw shows **no aliased partials** above −60 dB outside the expected harmonic
      series. **Test:** render, FFT, assert no out-of-series energy above threshold.
- [ ] `pulse_width` audibly and measurably changes the square's duty cycle / harmonic
      content across 0.1 / 0.5 / 0.9. **Test:** render three widths, compare even-harmonic
      energy.
- [ ] `NoteOn.arg0` sets pitch exactly: a `NoteOn` at 440 Hz produces a fundamental within
      ±0.1 Hz. **Test:** render, FFT peak detect.
- [ ] `phase_reset:true` makes two successive triggers start at identical phase (waveforms
      align); `phase_reset:false` they don't. **Test:** capture first-sample phase of two
      retriggers.
- [ ] Wavetable osc reads an uploaded table and is band-limited at high notes. **Test:**
      upload a known table, render high note, FFT for aliasing.
- [ ] No allocation on the audio thread while oscillators run. **Test:** allocation-counter
      stress check (same harness as Phase 0's "audio thread does no alloc" check).
